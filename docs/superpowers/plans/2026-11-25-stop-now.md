# Operator Stop (`stop --now`, SIGINT, SIGTERM) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the owner interrupt running work at once — `taskctl stop --now`, Ctrl-C or SIGTERM on `run`/`watch` — so that a confirmed interruption returns the task to `open` with no retry spent, and an unconfirmed one is recorded `uncertain` exactly as today.
**Architecture:** A new `src/stop.ts` owns the interrupt request on disk (`.taskctl/stop-now.requested`) and a per-controller `StopNow` source that every `runTask` races against its in-flight execution; a confirmed stop settles the attempt as "stopped by the operator" through the existing `controlled` / `checkpoint` path. `src/execution.ts` learns to confirm a cancelled process tree by the tree (a Windows process listing taken before the kill) instead of by the closure of its output pipes, and the CLI turns SIGINT/SIGTERM into the same request and maps the outcome to exit codes 0 / 130 / 143 / 1, ordered against part 1's 3 and its 1 (D1). The three schedulers (`runScheduler`, `runBatch`, `watchQueue`) stop claiming once the source has fired, and none of them takes part 1's outage decision under a stop (D13).
**Tech Stack:** TypeScript (NodeNext, strict), Node.js 22 (`node:child_process`, `node:fs/promises`), Vitest 5, Windows PowerShell (`Get-CimInstance Win32_Process`) for the process listing, `taskkill` for the tree kill; no new runtime dependency.
**Spec:** docs/superpowers/specs/2026-11-25-model-trouble-and-operator-control-design.md
**Runs after:** `docs/superpowers/plans/2026-11-25-model-refusals-and-stuck-list.md` (part 1 of the design, 17 tasks), as the design's §14 orders.

## Review Focus

Seven things the spec implies that would bite the owner first. None is exercised by a test today; each is pinned by the named test in the task that owns the code.

1. **The interrupted task is offered again by the controller that stopped it.** A task back in `open` is normally the scheduler's next offer (the handoff already recorded this hazard for `reject` under watch). Pinned by Task 7: `a stop interrupts every task in flight and offers nothing afterwards`, `nothing is claimed once a stop was already requested`, `claims nothing after the current task was … with a stop pending`, `an in-process stop interrupts the active task and ends watch without a file`; and through the real CLI by Task 8: `taskctl run observes stop --now from another process, returns the task to open and exits without re-claiming`.
2. **A cut gate, or a gate that ended as the stop arrived, is judged** — a retry spent, a failure streak started, a rework note written, `review-pending.json` created. Pinned by Task 6: `a stop during the acceptance command kills the gate and judges nothing`, `a gate that ended as the stop was observed is not judged`, `a stop during the review turn returns the task to open and writes no verdict`, and for the window after a telemetry call `a stop observed during telemetry spends nothing: a failed turn is not accounted` and `a stop observed during the reviewer's telemetry writes no verdict`.
3. **An unconfirmed kill presented as a clean stop** — status `open`, a `stopped` journal line, exit 0 or 130. Pinned by Task 5 `an unconfirmed cancellation is recorded uncertain and blocks, never as a clean stop`, Task 6 `a stop the real service does not acknowledge is recorded uncertain`, Task 8 `an unconfirmed stop exits 1, for %s` (a request from the board, and a signal).
4. **The rerun resumes the session that was cut** (or a later batch continues it). Pinned by Task 5 `the session a cut turn ran on is marked dirty, so the rerun starts a fresh one`, Task 6 `a stop during a real adapter turn asks the service to stop the observed session and confirms`, Task 7 `an interrupted batch turn returns its task to open and no later batch continues its session`.
5. **A stop request that outlived its controller** — `stop --now` typed while nothing ran, or the request a Ctrl-C'd predecessor left behind — stops a fresh `run` at once or makes `watch` unable to restart. Pinned by Task 1 `an interrupt older than the controller is ignored; a newer one is seen` and `a request removed after the controller started is not a stop`, Task 2 `watch --resume clears an interrupt request too` and `watch without --resume is refused while only an interrupt request exists`, Task 8 `a stop --now left by an earlier controller does not stop the next run` and `SIGINT on an idle watch exits 130 at once and leaves the stop request`.
6. **A stop mistaken for part 1's evidence.** Part 1 has the controller decide between a task's own problem and an outage once nothing is in flight. If the operator's stop is what drained the attempts, that decision would report an outage on evidence the run never collected, and a run stopped by the operator would end with part 1's report and exit code. Pinned by Task 7: `a run the operator stopped declares no outage`, `watch declares no outage under a stop`, `a stop ends a wait for a model window at once, and nothing is offered after it`.
7. **A guard refusal read as an interrupted attempt, or a stop read as a refusal.** A stop while the budget guard judges a task, or after it refused one: nothing was claimed and no session started. Pinned by Task 5 `a pending stop asks the guard nothing, and a refusal is not a stop` and `a stop that lands while the guard judges is seen before the claim`; by Task 4 `the gate and the agent CLI are insulated only when the controller asks` (its control-plane half); and by Task 8 `a run that refused a task and was then stopped exits 1 and says both`.

## Protocol for every code task (Tasks 1–8)

Each task's step 5 uses this procedure. It is the repository's protocol (handoff §4) written out once.

- **Control before.** Run the task's test files; every test must pass. Record `git hash-object <file>` for every source file the task changed.
- **One mutation at a time.** Apply it with a single edit, run only the test files the task names, and require the named test to FAIL for the stated reason. A mutation that survives is a test-design signal: strengthen that test (a direct assertion, not a looser threshold) and rerun. A constant-false guard in a mutation is a constant (`if (false)`), never two calls to a clock.
- **Restore.** Reverse the edit. Never `git checkout` / `git restore` here: the implementation is not committed yet. After each restore every recorded hash must be identical — the source is byte-identical.
- **Control after.** Run the task's test files again; every test must pass. If either control is not clean the whole round is void and is repeated.
- **Record.** Append name, killing test and result to `$env:TEMP\taskctl-stop-now-mutations.json` (outside the repository; never committed).
- **Serial.** An edit and the command that depends on it are issued one after the other, never in one parallel batch; never two edits to one file in one batch.

Per task: `npm run typecheck`, `npx tsc --noEmit`, `git diff --check`. The whole suite (`npm test`, about 35 s after this plan — every real cancel on Windows now spends about one second listing processes) runs at the end of Task 8 and of Task 10, not per task. The count to compare against is the one Task 1's control run prints: `865 passed / 1 skipped` at `0eb2d74`, plus whatever part 1 added before this plan ran. No number in this plan is a target on its own.

## Decisions taken where the spec is silent

The implementer follows these; the owner can overrule any of them before Task 8.

| # | Question the spec leaves open | Decision in this plan |
| --- | --- | --- |
| D1 | Exit code of `run` / `watch` after an interrupt | confirmed stop asked for by `stop --now`: **0**; by SIGINT: **130**; by SIGTERM: **143** (128 + signal number); any interrupted attempt that ended `uncertain`: **1**, whatever asked. A usage error stays 2. **When a stop and something else fall in one run, in this order:** (1) an interrupted attempt that ended `uncertain` → **1**; (2) an outage → **3**, whatever else happened (design §7, part 1) — it cannot meet an operator's stop, because no controller takes that decision under a stop (D13); (3) what makes today's `run` exit **1** anyway — a task blocked by a controller error, a task the budget guard refused (ADR-0012) — with the stop's report printed beside; (4) the operator's confirmed stop → 0 / 130 / 143; (5) otherwise 0. So a `stop --now` stop exits 0 only when the run has nothing else to report. `watch` keeps returning 0 after a guard refusal, as it does today. `retry --review-only`: part 1's closed window → 1, then the stop's code, then today's 1 for a recovery that was refused or unavailable. |
| D2 | Does Ctrl-C leave `.taskctl/stop.requested` behind? | Yes. "`SIGINT` and `SIGTERM` … do what `stop --now` does" is read literally: the handler writes the same two files, so a second controller on the board stops too and the next `watch` needs `--resume` (the restart path the README already documents). `run` ignores a request older than itself. |
| D3 | "the task returns to `open`" — also for `retry --review-only`? | It returns to the status it was claimed from (`r.task.status`, the copy of the board's task taken before the claim set it `running`). An explicit `retry --review-only` recovery claimed a `blocked` task that carries `review-pending.json`; a stop returns it to `blocked` with that file intact, so `retry --review-only` still works. Every other attempt returns to `open` — an automatic resumption of a deferred review included, which part 1 claims from `open` with its preserved evidence and its deferral, and which therefore goes back to `open` with both. |
| D4 | The render check is not a cancellable execution | It is not made one here. `--now` landing during a render check prints one line, lets the check end (each of its steps is bounded at 30 s), then judges nothing and returns the task to `open`. Its browser keeps today's spawn: a Ctrl-C that kills it ends the check, whose result is not judged anyway. Making it a cancellable `Execution` is a follow-up. |
| D5 | How "the tree is gone" is verified | Windows: one `Get-CimInstance Win32_Process` listing taken **before** the kill gives the live descendants by verified lineage; after the kill each must be gone, then the output pipes must close. A platform that cannot list (everything but Windows, or PowerShell unavailable) keeps today's rule: the utility's own report and the pipes. A process whose parent died before the cancel began cannot be attributed and still ends `uncertain`. The listing's own child shares the controller's console: a second Ctrl-C (D7) that lands on it costs the listing — the cancel then falls back to the utility's report, today's rule — and nothing else. *(2026-11-27 update: once the cancel is confirmed, the tree is confirmed by the tree itself, and the output pipes must still close; on Windows, when the listing cannot be taken, `taskkill`'s report stands in only for the step "are the descendants all gone", and the pipes still have to close. Without the last two a second Ctrl-C (D7) could kill the `session.interrupt` call and leave a clean stop `uncertain`, or cut the catalogue read and make the guard refuse a task it would have allowed. `add`, `split`, `verify`, `check`, `models` and `recall` install no handler (D10) and keep today's spawn. Verified only live (Task 12). *(2026-11-27 update: on Windows, insulation is a hidden console of the process's own — `windowsHide: true`, no `detached`; only other platforms get a process group of their own, `detached: true`. A process that is not detached and has no console of its own is not used because the programs it starts would not get their output back. `7c670ec` corrected this mechanism; D6's intent is unchanged. The `git` children a controller waits for — the sweep's untracked read, the review's changes read, the workspace reservation's common-dir read — are insulated the same way since `b2506e0`, by the owner's decision of 2026-11-27.)* |

| D8 | Plain `stop` and `run` | Unchanged: `run` ignores a plain `stop`; `watch` handles it gracefully. `stop --now` interrupts both. |
| D9 | What the cut turn leaves | No wrap-up prompt, no handoff note, no artifact sweep. The session recorded for the attempt is marked `clean: false`. A `done.requested` written during the cut turn is cleared. |
| D10 | Other commands and signals | Only `run`, `watch` and `retry --review-only` (which runs the same attempt code) install a SIGINT/SIGTERM handler. Every other command keeps Node's default — `models` and `recall`, which the learning loop added, included. |
| D11 | A stop that meets the budget guard | The guard's judgement is not interrupted. It is not an `Execution`; it is bounded (30 seconds per read, and only until a catalogue has been read once in that directory); and killing it would only make the guard refuse, since `src/budget.ts` fails closed on a catalogue it cannot read. What the interrupt does: a stop already pending is answered before anything is started — `runTask` returns `"skipped"` before the guard is asked, and again before the claim if the stop arrived while the guard judged. A refusal stays `refused`, stop or no stop: nothing was claimed and no session started, so it is not counted as stopped and no status moves; each scheduler keeps the handling of `refused` that the learning loop gave it and part 1 keeps. The catalogue read is kept out of the console's Ctrl-C by the adapter's insulation (D6, Task 4). |
| D12 | A stop that meets the memory recall | Not interrupted either. A stop that lands on it is seen when the recall ends, and nothing was interrupted: the attempt is settled as stopped, and its `recall.json` and journal line are the recall's own. The wait is visible: a `stop-requested` event says a recall is in progress, as it does for the render check (D4). The server is kept out of the console's Ctrl-C by the same insulation (D6, Task 4), switched on only for an attempt that has a stop source; `taskctl recall` keeps today's spawn. *(2026-11-27 update: the memory recall is never interrupted, only announced while it runs; it sets its own bound, ends its own server, and the loop's first stop check after the recall ends is what settles the attempt. `windowsHide: true` is what the memory server's spawn has always carried, and `taskctl recall`'s server on Windows has always been in a hidden console of its own, whatever the attempt's stop source. `7c670ec` corrected this sentence's mechanism.)* |
| D13 | A stop beside part 1's rounds and deferrals | (a) A stop writes no deferral and counts no round: the interrupted round is not a refused one. The entries the models that did refuse left in the shared cooldown table stay, being facts about those models. (b) **No controller takes part 1's outage decision under a stop.** The decision is taken once nothing is in flight; when the operator's stop is what drained the attempts, the run would report an outage on evidence it never collected — the anti-goal "a run stopped for an outage when the model was serving other tasks". So `runScheduler`, `scheduleOnce` and `runBatch` skip `settleExhausted` while a stop is pending; the task that ran out of rounds stays `open` with its spent record, which is where part 1's stuck list shows it as waiting for the owner, and the exit code is the stop's (D1). (c) A stop ends `run`'s wait for a model window at once, and the wait's timer is cleared, so a stopped `run` does not sit out the window after it has returned. (d) `watch --resume` clears the two stop files and nothing else: a deferral (`tasks/<id>/model-wait.json`) keeps its earliest time, and a new `watch` process is a new run, so its rounds start from 0 once that time has come; the queue's memory of refused tasks (`refusedAt`, `REFUSED_RETRY_MS`) is the old process's and dies with it. |

```ts
export type StopSignal = "SIGINT" | "SIGTERM";
export type StopSource = "file" | StopSignal;

export const stopRequestPath = (tasksDir: string): string;      // .taskctl/stop.requested, as today
export const stopNowRequestPath = (tasksDir: string): string;   // .taskctl/stop-now.requested
export const STOP_POLL_MS = 250;

/** Write a stop request. `now` writes the graceful request first, then the interrupt request; returns the path of the interrupt request for "now", else of the graceful one. Content is `${at.toISOString()}\n`. */
export function requestStop(tasksDir: string, mode: "graceful" | "now", at?: Date): Promise<string>;
/** Content of the interrupt request, or null when there is none. */
export function readStopNowRequest(tasksDir: string): Promise<string | null>;

export type StopNow = {
  /** Settles once an interrupt has been observed. Never rejects. */
  readonly observed: Promise<StopSource>;
  isRequested(): boolean;
  source(): StopSource | undefined;
  /** One look at the board: did an interrupt arrive since this controller started, or since the last look? */
  check(): Promise<boolean>;
  /** An attempt is about to run: watch for an interrupt until the returned function is called. */
  hold(): () => void;
};

export type SignalSource = { subscribe(listener: (signal: StopSignal) => void): () => void };
export function processSignalSource(): SignalSource;

export type StopNowOptions = {
  signals?: SignalSource;
  pollMs?: number;
  /** Called for every signal, first or repeated; its promise is awaited by `close()`. */
  onSignal?: (signal: StopSignal) => Promise<void> | void;
};
export function createStopNow(tasksDir: string, options?: StopNowOptions): Promise<StopNow & { close(): Promise<void> }>;
```

```ts
import type { SignalSource, StopNow, StopSignal, StopSource } from "../../src/stop.js";

/** An interrupt source a test fires by hand: no file, no clock, no signal. */
export function manualStopNow(): StopNow & { trigger(source?: StopSource): void } {
  let source: StopSource | undefined;
  let settle!: (value: StopSource) => void;
  const observed = new Promise<StopSource>((resolve) => { settle = resolve; });
  return {
    observed,
    isRequested: () => source !== undefined,
    source: () => source,
    check: async () => source !== undefined,
    hold: () => () => {},
    trigger: (from = "file") => {
      if (source !== undefined) return;
      source = from;
      settle(from);
    },
  };
}

/** Stands in for the process's SIGINT/SIGTERM: firing it never touches the real process. */
export function manualSignals(): SignalSource & { fire(signal: StopSignal): void } {
  const listeners = new Set<(signal: StopSignal) => void>();
  return {
    subscribe(listener) {
      listeners.add(listener);
      return () => { listeners.delete(listener); };
    },
    fire(signal) {
      for (const listener of [...listeners]) listener(signal);
    },
  };
}
```
