# taskctl v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个独立 CLI 编排器：批量发布 Markdown 任务 → 单 Worker 认领执行 → Context Budget 逼近阈值时自动交接延续（R4 核心）→ 验收关落锤 done → 自动找下一个任务。

**Architecture:** 编排器是 agent 无关的驱动层，经 Adapter 接口驱动 OpenCode（v0.1 唯一实现）：执行面用 `opencode run`（NDJSON 捕获 sessionID），控制面用 `opencode api`（tokens 用量 / model limit）。任务以 `tasks/` 下 Markdown + frontmatter 为真相源，认领用原子文件锁，agent 经 `taskctl done|note` 子命令与编排器通信（文件系统 marker）。**共识规格的裁剪**：`agents.yaml` 池与配置三层中的"agent 条目层"推迟到 v0.2（Kimi adapter 加入时一并落地），v0.1 以 `taskctl.json` 的 `agent`/`model`/`effort` 字段承载全局层 + task frontmatter 承载任务层。

**Tech Stack:** TypeScript (strict, ESM) + Node 22 LTS；运行时依赖仅 `gray-matter` + `js-yaml`；测试 vitest；进程一律 `node:child_process.spawn` 参数数组（禁 shell 字符串）。

**Spec:** `docs/adr/0001-0006` + `GLOSSARY.md`（术语）。执行者先读这两份。

## Global Constraints

- Node `>=22`；`tsconfig.json` strict、ESM（`"type": "module"`）；构建/测试经 `npx tsx` / `npx vitest`，产物 `dist/`
- 运行时依赖只允许 `gray-matter`、`js-yaml`；dev 依赖 `typescript`、`tsx`、`vitest`、`@types/node`、`@types/js-yaml`
- 所有外部进程用 `spawn(file, args[], {cwd, shell: false})`；路径拼接一律 `node:path`；禁 Unix-only API（flock/symlink/`/tmp`）
- 不读 OpenCode 的 SQLite，只经 `opencode run` / `opencode api`（输出均为单行 JSON 对象 `{"location":…,"data":…}` 或 `{"data":…}` 包装）
- `opencode` 二进制可经配置 `opencodeBin` 覆盖，默认 `"opencode"`
- 状态机：`open → running → done | blocked`；锁/marker/note 文件失败不得损坏 task 文件（写前 tmp+rename）
- 提交遵循 conventional commits（`feat:`/`test:`/`chore:`），每 Task 至少一次提交
- 测试不依赖真实 opencode：Adapter 测试注入 fake 二进制（见 Task 6）；真实链路只在 Task 10 E2E（`TASKCTL_E2E=1` 才跑）

## Review Focus

1. **Worker 崩溃留下 `running` + 过期锁** → 下次 `taskctl run` 须能接管（stale 判定测试，Task 3）
2. **Agent 回合结束但从不调 `taskctl done`** → 不得落 done；视为未完成，继续下一回合（Task 8）
3. **acceptance 命令非零退出** → 不落 done，`retries++` 重试；超 `retryLimit` 转 `blocked`（Task 5+8）
4. **`opencode run` 退出码非 0（回合失败）** → 记为该 session 一次失败重试，进程不得崩（Task 6+8）
5. **`taskctl note` 参数含换行/引号/中文** → note 文件内容逐字完整（Task 9）

### Task 6: OpenCodeAdapter

**Files:**

- Test: `tests/adapters/opencode.test.ts`、`tests/adapters/fake-opencode.mjs`

**Interfaces:**
- Produces (`src/adapters/types.ts`):
```ts
export interface AgentAdapter {
  prompt(args: { sessionId?: string; text: string; model?: string; effort?: string; title?: string; cwd: string }):
    Promise<{ sessionId: string; exitCode: number; text: string }>;
  contextUsage(sessionId: string): Promise<number>;       // tokens 总量

}
```
- Produces (`src/adapters/opencode.ts`): `class OpenCodeAdapter implements AgentAdapter`，构造 `constructor(opts?: { bin?: string })`；`prompt` = `spawn(opencodeBin, ["run","--format","json", ...(sessionId?["--session",sessionId]:[]), ...(model?["--model", `${model}${effort?`#${effort}`:""}`]:[]), ...(title?["--title",title]:[]), "--auto", text], {cwd})`，逐行解析 NDJSON（`JSON.parse` 失败跳过）：首个含 `sessionID` 的行记录 id、`type:"text"` 事件拼接 `text` 字段；`contextUsage` = `api session.get --param sessionID=<id>` → 取 `data.tokens` 的 `input+output+reasoning+cache.read+cache.write`；`contextLimit` = `api model.list` → `data[]` 中 `${providerID}/${id}` === model 或 `id` === model 去掉 provider 后匹配 → `limit.context`

### Task 8: Worker 主循环（R4 核心）

**Files:**
- Create: `src/worker.ts`
- Test: `tests/worker.test.ts`

**Interfaces:**
- Consumes: TaskStore(2)、claim/release/heartbeat(3)、writeNote/latestNote(4)、runAcceptance(5)、AgentAdapter(6)、buildWorkerPrompt(7)
- Produces: `type WorkerConfig = { tasksDir: string; workdir: string; agent: string; model?: string; effort?: string; contextThreshold: number; retryLimit: number; lockTtlMs: number; heartbeatMs: number }`；`runWorker(cfg: WorkerConfig, deps: {store: TaskStore; adapter: AgentAdapter}): Promise<{done: string[]; blocked: string[]}>`（跑完队列所有 open 任务后返回）
- Produces: 单任务执行序列 `runTask`：`claim` → `setStatus running` → 循环 { `buildWorkerPrompt`(注入 latestNote) → `adapter.prompt` → `appendSession` → 若 `readDoneMarker` → 跳出验 收；否则 `contextUsage/contextLimit` ≥ `contextThreshold` → 发收尾指令（Task 7 固定文案"上下文预算告急"）→ 等该回合结束 → `latestNote` 已更新则开新 session 继续，否则视为一次失败 } → 验收：`runAcceptance` passed → `setStatus done` + `release`；!passed → `incRetries`，retries < retryLimit → 重新开 session 继续；≥ → `setStatus blocked` + `release`

- [ ] **Step 1: 写失败测试** — 全部用 fake TaskStore（内存 Map）+ fake Adapter（脚本化返回）+ fake acceptance：
  - 正常路径：1 任务，第 1 回合后 done marker → acceptance passed → done
  - **Review Focus 2**：回合结束无 marker → 不落 done，发下一回合（fake 第 2 回合才置 marker）
  - **R4 交接**：fake contextUsage 首回合返回超阈值 → 断言收尾指令 prompt 发出、appendSession 两次、第 2 回合 prompt 含第 1 回合写的 note
  - **Review Focus 3**：acceptance 失败 3 次（retryLimit=3）→ blocked
  - **Review Focus 4**：prompt exitCode 1 计为失败重试，不 reject
  - 队列：2 任务顺序完成，返回 `{done:[a,b]}`

- [ ] **Step 2: 跑测试确认失败**

- [ ] **Step 3: 实现** — 注意：收尾指令后新 session 的 note 若缺失（agent 没写）→ 编排器自写兜底 note（status="orchestrator-fallback"，done/next 摘自任务与回合输出首 500 字）。

- [ ] **Step 4: 跑测试确认通过**
